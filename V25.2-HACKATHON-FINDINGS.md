# V25.2 Hackathon Findings

Curated proposals for issues to file against `vaadin/*` repos and link
from `vaadin/platform#8820` ("Platform 25.2 PiT Issues") under the
**Hackathon Findings** section. Grounded in
`V25.2-MODERNIZATION-REPORT.md`.

Each row records:

- **Title**: the proposed issue title.
- **Repo**: target `vaadin/*` repository.
- **Type**: `bug` / `enhancement` / `docs`.
- **Priority**: P1 file now, P2 worth filing, P3 nice to have.
- **Duplicate check**: result of `gh search issues` plus targeted
  cross-checks. Either `New` or `Possible dup: #NNNN <title>`.
- **Evidence**: `path:line` in this branch that motivates the proposal.
- **Why it matters**: one sentence on user / DX impact.

No bodies are pre-written. Pick a row, open the evidence, read the
linked duplicate (if any), and decide whether to file fresh, comment on
the existing issue, or skip.

Wrapping a Signal in a `ValueSignal<Signal<T>>` already gives swap-aware reads with plain `Signal.computed`: when the outer ValueSignal is reassigned, the consuming Effect re-evaluates, reads the new inner Signal, and re-subscribes (unsubscribing the old one). Verified in a temporary `/dyn-signal-test` view: with `outer = ValueSignal<Signal<Boolean>>(inner1)` and `Signal.computed(() -> outer.get().get())` bound to a Span text, flipping inner1, swapping outer to inner2, then flipping inner1 (decoupled) and inner2 (now tracked) all behaved as expected. The trick is to read through one extra signal hop. | No issue. Optional showcase improvement: refactor `components/stepper/Wizard.java` to replace `Signal<Boolean>[] stepValidity` plus `ValueSignal<Integer> validityRevision` (lines 55-56, 72-79, 172-173) with a single `ValueSignal<Signal<Boolean>> currentStepValidity`. Removes the touch-signal pattern and the `@SuppressWarnings("unchecked")` on the generic array creation. |

## How to use this file

1. Pick a row from the **Findings to file** table.
2. Open the **Evidence** `path:line` in this branch to read the
   motivation in context.
3. Read the **Duplicate check** column. If "Possible dup" or "Related",
   open the linked issue first; decide whether to file a refinement,
   comment on the existing issue, or skip.
4. If filing fresh:

   ```bash
   gh issue create \
       --repo vaadin/<repo> \
       --title "<title from this table>" \
       --body "$(cat <<'EOF'
   ### Describe your motivation

   <pull from V25.2-MODERNIZATION-REPORT.md the relevant subsection>

   ### Describe the solution you'd like

   <copy the API sketch from the same subsection of the report>

   ### Describe alternatives you've considered

   <mention the workaround currently used in the showcase>

   ### Additional context

   Surfaced during the Vaadin Showcase modernization to 25.2.0-beta1.
   See `<repo-link>/V25.2-MODERNIZATION-REPORT.md` and the
   `vaadin/platform#8820` umbrella.
   EOF
   )"
   ```

5. Once filed, paste the URL under the **Hackathon Findings** section of
   `vaadin/platform#8820`.
